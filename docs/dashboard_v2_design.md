# Dashboard OS Ver.2 設計書

## 1. 設計思想

このダッシュボードは、毎日の生活・発信・思考を無理なく回すための個人OSとして設計する。

最優先するのは「毎日使えること」。  
多機能さよりも、開いた瞬間に今日やることが見えること、入力が重くないこと、同じ情報を何度も書かなくて済むことを重視する。

### 基本方針

- 毎日使うことを最優先する
- 入力項目は最小限にする
- 同じ情報を二重入力しない
- ホームは「今日を始める場所」にする
- 各ページは独立して完結させる
- 必要になったらページを増築する
- 最初から作りすぎない
- デザインより使いやすさを優先する
- 設計書にない項目を実装中に勝手に追加しない

## 3. 各ページ詳細

## ホーム

ホームは、このOSの起点。  
朝に開いて「今日をどう始めるか」を決め、必要なページへ移動するための場所にする。

### 項目

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| 今日の始まり | 今日の日付、開始時刻、ひとこと | 今日の開始を記録できる |
| 睡眠 | 合計睡眠時間、睡眠回数、最長睡眠時間、一言 | ライフ > 睡眠と情報を共有し、二重入力しない |
| 今日できること | 表情、気分、読む、書く（新規記事）、コメント・交流、掃除・家事、実装・開発 | ○・△・×を中心にワンタップで選べる |
| 今日の用事 | 今日ある予定・外せない用事 | 短く入力できる |
| タスク | 今日やること | チェックできる。増やしすぎない |
| メール | 確認が必要なメール | 未確認・対応済みを分けられる |
| DM | 確認が必要なDM | 未確認・対応済みを分けられる |
| 10時以降モード | Seed、読書、Brain、生活、発信 | 複数選択でき、日付別データとして保存される。翌日は未選択に戻る |
| 各ページへの入口 | 発信・思考・ライフへのリンク | ホームから迷わず移動できる |

### ホームでやらないこと

- 発信記事の詳細管理
- 読書メモの長文入力
- 睡眠ログの詳細分析
- 複雑なタスク管理

ホームはあくまで「今日を始める場所」とし、詳細は各ページに任せる。

## 発信

発信ページは、複数媒体の投稿状況を一か所で見渡す場所。  
媒体ごとに役割が違うため、Substack、note、X、WordPressを分けて管理する。

### Substack

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| ネタ | 書きたいテーマ | 下書き前のアイデアを保存できる |
| 下書き | タイトル、本文メモ、状態 | 執筆中・公開済みなどの状態を持てる |
| 公開予定 | 公開日、優先度 | 予定が見える |
| 公開後メモ | 反応、改善点 | 次回に活かせるメモを残せる |

### note 1: AI × 生活・回復

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| ネタ | AI、生活、回復に関するテーマ | 思いついた時に軽く保存できる |
| 下書き | タイトル、概要、本文メモ | 執筆の進捗を管理できる |
| 公開状態 | 未着手、執筆中、公開済み | 状態を切り替えられる |
| 振り返り | 読者反応、次に書くこと | 公開後に短く記録できる |

### note 2: Substack初心者向け

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| ネタ | 初心者が困ること、解説テーマ | テーマをストックできる |
| 記事案 | タイトル、対象読者、結論 | 初心者向けとして整理できる |
| 進捗 | 未着手、執筆中、公開済み | 状態を管理できる |
| 補足メモ | 次に深掘りすること | 連載化しやすくする |

### X

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| 投稿ネタ | 短文アイデア | すぐ保存できる |
| 投稿文 | 実際に投稿する文章 | コピーしやすい形で表示する |
| 状態 | 未投稿、投稿済み | 投稿済みチェックができる |
| 反応メモ | 伸びた投稿、気づき | 次の投稿に活かせる |

### WordPress

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| 記事テーマ | SEO記事・ブログ記事のテーマ | 記事候補を保存できる |
| 下書き | タイトル、構成、本文メモ | 記事制作の進行を管理できる |
| 公開状態 | 未着手、執筆中、公開済み、リライト候補 | 状態を切り替えられる |
| リライトメモ | 修正点、追加したい内容 | 改善対象を残せる |

## 思考

思考ページは、まだ形になっていない考えを置く場所。  
発信やタスクにすぐ変換しなくてもよい。Seed、読書、メモを分けて扱う。

### Seed

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| 種 | 思いついた考え、違和感、問い | 短く保存できる |
| 分類 | 発信候補、生活、仕事、学びなど | 後から探しやすくする |
| 状態 | 未整理、育てる、発信へ | 考えの成長段階を見える化する |
| 次の一歩 | 調べる、書く、寝かせる | 思考を止めずに置いておける |

### 読書

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| 本の情報 | 書名、著者 | 読書記録を残せる |
| 読書メモ | 印象に残った内容、引用、考え | 長すぎないメモとして保存できる |
| 状態 | 読みたい、読書中、読了 | 読書状況を管理できる |
| 発信候補 | 記事や投稿に使えそうな点 | 発信ページへつなげられる |

### メモ

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| メモ本文 | その場で残したいこと | すぐ書ける |
| タグ | 任意の分類 | 後から探せる |
| 状態 | 未整理、保存、発信候補 | メモの扱いを決められる |
| 関連先 | 発信、Seed、読書など | 必要に応じて別ページへつなげられる |

## ライフ

ライフページは、生活の土台を記録する場所。  
最初は睡眠だけを扱い、必要になったら項目を増やす。

### 睡眠

| 項目 | 入力内容 | 必要な機能 |
|---|---|---|
| 就寝時刻 | 寝た時間 | 睡眠ログとして保存できる |
| 起床時刻 | 起きた時間 | 睡眠時間を計算できる |
| 睡眠時間 | 自動計算または手入力 | ホームにも反映する |
| 睡眠の質 | ○・△・×、または短い選択肢 | 朝の状態とつなげられる |
| メモ | 眠れなかった理由、起床時の感覚など | 必要な時だけ書ける |

## 4. ホーム詳細設計

ホームは「今日を始める場所」として、朝に必要な判断だけに絞る。

### 今日の始まり

- 今日の日付を表示する
- 開始時刻を記録する
- 今日のひとことを入力できる

### 睡眠

ホームの睡眠欄は、以前作成した体調チェック項目を再利用する。
入力先を増やさず、既存の `healthState` を更新する。

当初の睡眠要約としては、既存の `healthState` から以下の4項目を表示できる。

- 合計睡眠時間
- 睡眠回数
- 最長睡眠時間
- 一言

既存データとの対応:

- 合計睡眠時間: `sleepHours`
- 睡眠回数: `sleepCount`
- 最長睡眠時間: `longestSleepMinutes`
- 一言: `bodyNote`

詳細入力はライフ > 睡眠で扱う。  
ホームとライフで二重入力しない。

### 今日できること

既存の `capacityCheck` を再利用する。

表示する項目:

- 表情
- 気分
- 読む
- 書く（新規記事）
- コメント・交流
- 掃除・家事
- 実装・開発

Seed、読書、メモは独立ページにするため、この○△×には含めない。

選択肢は細かくしすぎない。  
今日の動き方を決めるための最小限の入力にする。

### 今日の用事

- 今日外せない用事を短く書く
- 予定の詳細管理はしない
- ホームでは「今日それがある」とわかればよい

### タスク

- 今日やることだけを表示する
- チェックできる
- 多すぎるタスクを前提にしない

### メール

- 確認が必要なメールを置く
- 対応済みにできる
- メール本文の詳細管理はしない

### DM

- 確認が必要なDMを置く
- 対応済みにできる
- DM本文の詳細管理はしない

### 10時以降モード

朝の立ち上がりが終わった後に、作業モードへ切り替えるための領域。

候補:

- Seed
- 読書
- Brain
- 生活
- 発信

チェックボックス形式で複数選択できる。  
日付別データとして保存し、翌日は未選択状態に戻る。
表示は横並びを基本とし、項目名が縦書きに見えないようにする。

### 各ページへの入口

ホームには以下の入口を置く。

- Substack
- note（いつものnote）
- note（Substack初心者向け）
- X
- WordPress
- Seed
- 読書
- メモ

入口は大きく、迷わず押せる形にする。
現時点では詳細ページを実装せず、入口と表示切替の土台だけ用意する。

## 5. 実装ルール

Codexで実装する時は、以下のルールを優先する。

### 基本ルール

- 今のダッシュボードをベースに Ver.2 としてリファクタリングする
- デザインより使いやすさを優先する
- 1ページずつ実装する
- 既存機能は活かせるものを活かす
- 設計書を優先する
- 実装中に勝手な項目追加をしない
- 最初から全ページを作り込みすぎない
- ホームを先に作る
- 各ページは単体で使える状態にする

### 実装順

1. ホーム
2. ライフ > 睡眠
3. 発信
4. 思考
5. 必要に応じた追加ページ

### UI方針

- 朝に開いて迷わない画面にする
- 入力欄は少なくする
- 選択式で済むものは選択式にする
- 長文入力をホームに置かない
- チェック、状態変更、ページ移動をすぐできるようにする
- 各ページの役割を混ぜない

### データ方針

- 同じ情報を複数ページで重複保存しない
- ホームは必要な情報を参照・要約する
- 詳細データは各ページに持たせる
- 後から項目追加しやすい形にする
